# 隐私边界

## 公开内容的来源

公开包由独立编写的通用代码、说明文档、环境声明、测试、演示配置和确定性的
合成 JSON 构成。合成示例仅来自固定模板和简单运算，不读取真实记录、私人
编号、日期、来源规模、分布、统计值或模型参数。

通用名称采用实体、信号、回复和区间，不附带与私人应用的对应表。公开代码
仍然展示其算法和数据结构；改为中性名称不能隐藏算法本身，也不是匿名保证。

程序不发出网络请求。使用者若输入私人资料，其生成的摘要同样属于私人派生
内容，不能因使用公开程序处理过就直接公开。`synthetic: true` 只是输入标签，
不能证明数据的来源或安全性。

## 发布器的检查

- 只允许固定白名单中的文件。白名单外且不在明确排除目录中的文件会阻止发布。
- 在源码树任何层级发现名称为 `private_data` 或 `local_runs` 的条目时，立即
  停止打包。空目录、文件、大小写变体和排除目录内的同名条目也会阻止发布。
  检查这些名称时不读取其内容，也不把匹配内容写入日志。
- `.git`、`.venv`、`venv`、`__pycache__`、`build`、`dist` 不打包；发布器仍检查
  它们内部是否出现上述禁止名称。排除目录不能用作存放私人数据的安全边界。
- 拒绝符号链接、目录联接和其他重解析点，避免间接纳入外部文件。
- 仅允许限定大小的 UTF-8 文本，扫描常见凭据形态、邮箱和本机绝对路径。
- 合成示例必须与生成器完全一致，预期摘要必须与当前程序重新计算的结果一致。
- 拒绝 JSON 重复字段，防止在解析时被丢弃的字段夹带额外内容；准备工具还会
  重新生成并核对清单的规范字节，避免清单中残留未验证的文字。
- ZIP 清单仅记录公开文件的相对路径、字节数和 SHA-256。文件时间与权限使用
  固定值，不写入机器名、用户名、实际修改时间、Git 作者或远程地址。

上述检查不是万能的秘密检测器。符合语法的真实事件、看似普通的敏感数字、
隐含身份信息以及没有匹配到的凭据仍可能通过文本检查，必须人工审核全部
公开内容。禁止名称规则也不能识别换成其他名称的私人文件。

## 隔离发布与后续沟通

只能从已审核的归档开始发布。准备工具验证归档总哈希、内部哈希、文件清单及
目标路径，并要求解压到整个私人工作区之外的新目录。不得复制私人项目的
Git 记录。随后仅对公开清单内的文件建立新的提交；具体流程见
[发布步骤](PUBLISHING.md)。`.gitignore` 不会清除历史提交，也不能约束手动上传。

[贡献规则](../CONTRIBUTING.md) 同样适用于 Issues、PR、Discussions、提交说明、
发布说明和附件。禁止真实数据及其派生统计、截图、日志、权重、缓存、真实
编号、机构信息、个人路径和可识别元数据。公开问题只能使用重新构造的虚构
最小示例；改名、抽样、加噪或删除部分字段不会自动使真实来源内容变为合成。

账号资料、仓库介绍、提交作者、活动时间和平台页面不在归档检查范围内。
这些信息和公开算法可能被外部信息关联，因此不能承诺绝对匿名或无法反推。
发布前需要单独确认拟使用的公开身份与页面信息是否符合保密要求。

以后每次修改代码、文字、示例或授权说明，都要重新检查、测试、打包和审核。
加入真实或真实派生内容后，原先对归档的审核结论不再适用。
